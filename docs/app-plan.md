# E&B's own code: where to start (proposal)

Status: decided (D6-D8), historical; written 2026-10-23. Current state and order: progress.md and
kernel-map.md.

## 1. What the app region is

The app region of client.exe (0x401000-0x8C1B50) holds E&B's own objects, linked incrementally.
From docs/app-inventory.md (tools/re/app_inventory.py) and the measurements below:

| | Functions | How known |
|---|---|---|
| All functions (incremental-link thunk targets) | 18,690 | the thunk table |
| Attributed to an original source file | 5,898 | 2,366 by their own `__FILE__` (assert) reference, the rest by lying between two functions of the same file (a heuristic: an object's functions stay together) |
| Named by a `Class::Method` string they use | 180 | profile labels and assert messages |
| VC6 standard-library template code (`std::vector`, `map`, `list`, `string`, ...) | about 340 certain (64+ bytes), up to about 2,900 counting short ones | a corpus of explicit instantiations compiled with VC6 SP4 and byte-matched (`.work/stl`, see below) |
| Inline virtuals of library classes compiled into E&B's objects | a few hundred | reached through vtables (docs/data/symbols.json, source `vtable`) |
| C++ exception-handling stubs for these functions | (separate region, 0xAA1C00-0xAE2830) | generated by the compiler with `/GX` |

So roughly 15,000 functions are E&B's own hand-written code: the real work.

The template corpus also confirms E&B's app code was compiled with **`/GX`** (exception handling):
compiled with `/GX` the corpus matches 533 functions, without it 501. Other flags are presumably
the libraries' (`/MT /O2 /Ob2`); the first reconstructed file will settle that.

By directory (attributed functions): `app\client` 3,898, `app\shared` 804, `app\common` 353,
`app\packets` 247 (+124 `gameedit`), `app\shared\auxdata` 114, `app\audio` 88,
`app\client\tasks` 82, `app\client\item` 59, `app\shared\expr` 50, `app\wwudp` 26,
`app\kernel` 18, `app\input` 11.

## 3. Proposed order

| # | Area | Why first | Size |
|---|---|---|---|
| 1 | `app\shared\auxdata` (Delta classes, codec) | the best-understood part of the client (earlier protocol research: address catalogue, field model, wire format, schemas, a codec that round-trips 43,978 EA messages); self-contained; everything game-state depends on it | ~114 attributed |
| 2 | `app\wwudp` (`CordMgr`, `CordCon`) | E&B's reliable UDP transport, small, and the earlier protocol research describes what it does | ~26 |
| 3 | `app\kernel`, `app\main`, `app\client\tasks` | the program's skeleton: `KernelClass::Run_One_Cycle`, the task classes (`LoginTaskClass`, the game task); gives a runnable frame to hang everything else on | ~100 |
| 4 | `app\packets` | the packet classes (`XxxPacketClass::Process_Packet`, ~100 named in strings), mechanical once the base class is known; matches the earlier research's message models | ~370 + clientstub |
| 5 | `app\common`, `app\shared` (rest) | shared definitions (races, items, factions), attributes (`AttribDir`), physics (`px*`) | ~1,150 |
| 6 | `app\client` | UI, gadgets, camera, rendering: the bulk | ~3,900+ |

## 4. Decisions for the user

Decided 2026-10-23 (docs/progress.md §2): **D6** the order above; **D7** byte-exact everywhere,
revisited with the user if it becomes too costly; **D8** no hybrid for now. The questions as
they were put:

* **D6. Start where?** The order above, or another (for example straight to the task kernel for a
  runnable skeleton).
* **D7. Byte-exact everywhere?** The libraries are held to byte-exactness. For E&B's code the same
  rule gives certainty but costs time on every function; an alternative is byte-exact for
  protocol, game-state and file-format code, and behaviour-equivalent (tested) for UI code.
* **D8. A running client when?** Reconstructed files can be linked into a client only when enough
  of the program exists; until then the work is proven function by function. Whether to aim
  early for a hybrid (reconstructed code patched into the retail client, function by function)
  is a separate choice: it would let each reconstructed function be tested live.
