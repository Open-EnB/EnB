## Concrete positive mechanism and remaining residue

Retail 0x76DB7C sign-extends code, spills that index at frame slot0x3c, loads len, spills len at0x4c and copies len into EBP at0x76DB92 BEFORE either eligibility branch. The previous actual early_size body held the index in EBP through the failed tests and copied i=len only inside the successful direct-copy branch. Assigning the genuine reverse counter before the condition forces the index spill and explains the missing four-byte frame slot exactly: frame0x3c becomes0x40. Many formerly different register ties, slot roles and entire later blocks also become retail's. This is the main positive result; it changes a real local lifetime rather than inventing padding or a frame object.

The prior explicit initialization order, tested in this new context, reproduces retail's oc/ycount/top_slot/xcount/fc stores. Reordering the independent reset stores makes another distinct actual code change in the expected direction.
