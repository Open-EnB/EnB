===========================================================================

stored but unread. They ARE read, through a real Vector3 copy constructor, and

The consumer which earlier audits missed
---------------------------------------
At the new-state constructor, two Vector3 arguments are materialized by value.
The stack evolution is exact, with signed hexadecimal deltas from B:

  7950D2 lea eax,[esp+34]                source=B+30 (end_up)
  7950DC sub esp,0c                      ESP=B-10 (end_up argument)
  7950E5 push eax                        ESP=B-14

  7950EB sub esp,0c                      ESP=B-1c (start_up argument)
  7950EE lea edx,[esp+dc]                source=B+c0 (configured_up)
  7950FB push edx                        ESP=B-20
  7950FC call416BA8 ->499720             ESP=B-1c after ret4
  795109 push end_time                   ESP=B-20
  79510A push start_time                 ESP=B-24
  79510B call40D576 ->718510             ESP=B after ret24

The decisive arithmetic is dc-1c=c0, NOT b4. 416BA8 is a direct jump to499720.
499720 reads three dwords at source+0/+4/+8 into destination ECX and returns
with ret4 at499736. Its cleanup pops its pointer argument; the12bytes reserved
for the by-value Vector3 remain on the caller's stack until718510 returns.
This is an actual address escape and read, even though the caller contains no
explicit fld/mov read of [B+c0]. Direct-load-only scanning cannot establish
that a stack object is dead.

The current existing prototype in app/client/postate.h:300 is
  (int start_time,int end_time,Vector3 start_up,Vector3 end_up,state).
Retail718537/49/50/57 stores the first vector into object+10/+14/+18, matching
StartUp. The second vector goes to+1c/+20/+24, matching EndUp. The constructor
returns ret24 at718600. It is already exact in docs/data/imports/app/postate.json.
The source implementation initializes those real members from those arguments.
No prototype, layout, ownership, helper, member, qualifier or global header
change is proposed. The later orientation method uses StartUp and EndUp for
the spline state's up-vector interpolation; it is itself partly reconstructed,
so the direct constructor stores, not that method's source, decide this audit.

The independently computed tangent0 remains atB+b4/b8/bc. Retail794F6A/71/78
writes its arithmetic result, and795137/3E passes B+b4 twice to Set_Tangents.
It is not the first constructor vector. Default up atB+30 is still the vector
used by the matrix multiplication and the second constructor vector. Thus the
configured up is used as the initial up, without replacing the default end up
or adding another normalization/rotation of the configured values.
